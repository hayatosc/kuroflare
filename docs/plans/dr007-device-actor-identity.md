# DR-007 Device and Yjs Actor Identity Plan

## Decision

- Use `deviceId` as the only authenticated and audited client identity.
- Remove `yClientId` from setup, Hello, session, storage, scripts, and security claims.
- Keep protocol version 1 because the wire contract has not been distributed or frozen.
- Let every persistent `Y.Doc` instance use the fresh actor ID generated by Yjs.
- Treat persistence loss as a new document epoch. Do not open a missing y-indexeddb
  database until recovery evidence has been evaluated.
- Recover by merging the authoritative remote state, the latest local-store YDoc base,
  and retained pending Y-update outbox records before writes and background queues resume.
- Fail closed for an affected document when database-directory, remote authority, local
  base, or pending-update evidence cannot be validated.

## Implementation order

1. Remove the unused actor claim from the active protocol.
   - Delete `yClientId` from setup and Hello schemas, persisted setup metadata, Worker
     sessions, smoke/import scripts, and related tests.
   - Remove registry allocation and mismatch admission decisions.
   - Update specifications so `deviceId` is authentication and audit identity, while
     Yjs actor IDs are CRDT implementation details rather than authorship claims.

2. Make durable audit identity explicit.
   - Add a Worker SQLite migration that records `device_id` on operation-log rows and
     removes active dependence on `y_client_id` from devices, operation logs, and
     connected-device records.
   - Rebuild affected tables atomically for existing development databases and define
     the clean schema directly for fresh databases.
   - Keep document update bytes authoritative for CRDT causality; do not infer actor
     authorship from the authenticated device.

3. Add document-epoch evidence to local-store schema version 4.
   - Store one epoch record per meta/file document independently from YDoc snapshot
     records, because local snapshots are not rewritten for every local edit.
   - Record the provider database name, fresh epoch identifier, recovery status, and
     the state-vector/base evidence used to complete recovery.
   - Migrate existing readable local stores without fabricating persistence-presence
     evidence. The first verified provider probe establishes the initial epoch.

4. Probe y-indexeddb databases before opening them.
   - Reuse the non-creating `indexedDB.databases()` directory-probe pattern.
   - If the API is unavailable, fail closed instead of opening a possibly missing
     provider database.
   - If an epoch exists but its provider database is absent, mark only that document as
     recovering and allocate a fresh Yjs actor after recovery inputs are ready.

5. Implement epoch recovery as a guarded merge.
   - Block editor mutations, metadata mutations, WebSocket requests, and outbox leasing
     for the affected document while recovery is active.
   - Fetch the latest authoritative remote document state.
   - Apply the validated local-store YDoc base when it contains state not yet represented
     remotely, then replay retained pending Y-update outbox bytes idempotently.
   - Create the fresh provider database only after the merge plan is validated.
   - Persist the new epoch, merged YDoc base, remote cursor, and recovery completion in
     one local-store transaction before background queues resume.
   - Keep the document blocked with actionable repair evidence when any dependency is
     missing or malformed; never discard pending outbox updates.

6. Add acceptance evidence.
   - Independent persistent documents and replacement epochs receive different real
     `Y.Doc.clientID` values.
   - Restart with intact persistence keeps valid clock history without claiming a stable
     device-wide actor.
   - Meta and file provider loss never reuses an actor with a reset clock.
   - Provider probing never creates a missing database.
   - Remote state, local base, and pending updates converge after recovery, including an
     already-durable duplicate update.
   - Recovery blocks edits and sends until the epoch transaction commits.
   - Setup, Hello, append, and operation-log tests prove that `deviceId` is the only audit
     identity and no envelope value can claim Yjs authorship.

7. Update status and run the complete quality gate.
   - Update protocol, data model, client, server, operations, design-review, and
     implementation-status documents.
   - Run format, lint, type-aware lint, typecheck, unit tests, Worker E2E, build, and an
     independent data-loss/security review before commit.

## Assumptions

- No distributed client or server depends on the current required `yClientId` fields.
- Existing development Worker and local-store databases should migrate without manual
  deletion even though rolling wire compatibility is out of scope.
- The authenticated latest-snapshot route remains the remote recovery authority.

## Out of scope

- Verifying update-internal Yjs actor IDs against `(deviceId, docId, epoch)` registries.
- Rolling compatibility with the superseded `yClientId` wire contract.
- General capability negotiation (DR-012).
- Generalized quarantine/error evidence (DR-009).
